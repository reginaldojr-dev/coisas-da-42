Get Next Line — Aula para Defesa

Explicação completa do mandatory: algoritmo, funções, memória e casos de teste.

Visão geral

1. O que é o projeto?

Get Next Line é um projeto da 42 em C cujo objetivo é implementar a função char *get_next_line(int fd);.

Ela deve ler de um file descriptor e retornar uma linha por chamada.

A linha retornada deve incluir \n quando ele existir. Se o arquivo terminar sem \n, a última linha deve ser retornada sem ele. Quando não houver mais nada para ler ou ocorrer erro, a função deve retornar NULL.

Frase para defesa:
“O projeto ensina leitura incremental, memória dinâmica e preservação de estado entre chamadas usando variável estática.”
Conceitos base

2. Conceitos fundamentais

2.1 File descriptor

Um file descriptor é um número inteiro usado pelo sistema operacional para identificar um recurso aberto, como arquivo, terminal, pipe ou entrada padrão.

FDSignificado
0Entrada padrão — stdin
1Saída padrão — stdout
2Saída de erro — stderr

2.2 read()

read() pede ao sistema operacional para ler bytes de um file descriptor. Ela não entende linhas; ela apenas lê bytes.

Retorno de read()Significado
> 0Quantidade de bytes lidos
0EOF — fim do arquivo
-1Erro de leitura

2.3 BUFFER_SIZE

BUFFER_SIZE define quantos bytes o read() tenta ler por vez. Ele é definido em tempo de compilação com a flag:

cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 get_next_line.c get_next_line_utils.c

O código deve funcionar com valores como 1, 42, 9999 e valores altos.

2.4 Variável static

A variável static mantém seu valor entre chamadas da função. No GNL, ela guarda a parte da leitura que já foi lida, mas ainda não foi retornada ao usuário.

Exemplo:
Se o programa leu "abc\ndef", a primeira chamada retorna "abc\n" e guarda "def" para a próxima chamada.
Algoritmo

3. Fluxo geral do algoritmo

1. Validar fd e BUFFER_SIZE
2. Ler do fd e acumular no remainder/stash
3. Parar ao encontrar '\n' ou EOF
4. Extrair a linha que será retornada
5. Atualizar o remainder/stash com a sobra
6. Retornar a linha

A escolha do algoritmo com string acumulada é simples, clara e adequada para o mandatory. Ele não é o mais otimizado para linhas gigantes, mas é suficiente para o objetivo do projeto.

Função principal

4. get_next_line

A função get_next_line coordena o fluxo principal do projeto.

Responsabilidades

  • Validar fd e BUFFER_SIZE.
  • Manter uma variável static com os dados pendentes.
  • Chamar a função que lê e acumula dados.
  • Extrair a linha atual.
  • Atualizar a sobra para a próxima chamada.
  • Retornar a linha ou NULL.
Frase para defesa:
“A get_next_line organiza o fluxo e delega leitura, extração e limpeza para funções auxiliares.”
Leitura

5. read_to_stash / read_to_remainder

Essa função lê do file descriptor e acumula o conteúdo até encontrar um \n ou até o read() chegar ao EOF.

Responsabilidades

  • Alocar um buffer temporário de tamanho BUFFER_SIZE + 1.
  • Ler dados com read().
  • Tratar erro de leitura -1.
  • Finalizar o buffer com \0.
  • Concatenar o buffer ao conteúdo acumulado.
  • Parar quando encontrar \n ou EOF.
  • Liberar o buffer temporário antes de retornar.
Ponto crítico:
Sempre verificar se read() retornou -1 antes de fazer buffer[bytes] = '\0'. Se bytes == -1, acessar buffer[-1] causaria comportamento inválido.

Memória

O buffer temporário pertence a essa função e deve sempre ser liberado. O acumulado pertence ao fluxo do GNL e pode ser atualizado pela função de join.

Extração

6. extract_line

Essa função cria a linha que será devolvida ao usuário.

Responsabilidades

  • Percorrer o acumulado até encontrar \n ou \0.
  • Se encontrar \n, incluir esse caractere na linha.
  • Usar uma função de substring para criar uma nova string.
  • Retornar essa nova linha.
AcumuladoRetorno esperado
"abc\ndef""abc\n"
"abc""abc"
""Não deve gerar linha válida
Frase para defesa:
“A extract_line não altera o acumulado original. Ela apenas cria uma nova string contendo a próxima linha a ser retornada.”
Limpeza

7. clean_stash / clean_remainder

Depois que uma linha é retornada, essa função remove do acumulado a parte que já foi entregue e guarda somente o que sobrou.

Responsabilidades

  • Encontrar o primeiro \n.
  • Se não houver \n, liberar o acumulado e retornar NULL.
  • Se houver sobra depois do \n, duplicar essa sobra.
  • Liberar o acumulado antigo.
  • Retornar a nova sobra.
acumulado: "abc\ndef"
linha retornada: "abc\n"
nova sobra: "def"
Ponto crítico:
Se não existe nada depois do \n, evite manter memória desnecessária para string vazia.
Utils

8. Funções utilitárias

8.1 ft_strlen

Conta o tamanho de uma string até encontrar \0. É usada para calcular tamanhos antes de alocar memória.

8.2 ft_strchr

Procura a primeira ocorrência de um caractere dentro de uma string. No GNL, verifica se o acumulado já contém \n.

8.3 ft_strjoin

Junta o conteúdo acumulado com o buffer recém-lido. Nesta implementação, ela é específica do GNL: além de concatenar, também libera o acumulado antigo.

Ownership:
Se a ft_strjoin consome o acumulado antigo, quem chama não deve tentar liberar esse ponteiro novamente.

8.4 ft_substr

Cria uma nova string a partir de uma posição inicial e de um tamanho máximo. É usada para extrair a linha que será retornada.

8.5 ft_strdup

Duplica uma string alocando nova memória. É usada para guardar a sobra depois da linha retornada.

Defesa

11. Como explicar na avaliação

Resumo oral

“Minha implementação usa uma variável estática para preservar os dados que já foram lidos, mas ainda não foram retornados. A função lê blocos de tamanho BUFFER_SIZE, acumula esses dados, procura por uma quebra de linha, extrai a linha atual e atualiza a sobra para a próxima chamada.”

Sobre memória

“Cada linha retornada é alocada dinamicamente e deve ser liberada por quem chamou a função. Internamente, eu libero buffers temporários e substituo o acumulado antigo pela nova sobra quando necessário.”

Sobre read

“Eu trato os três retornos possíveis de read: bytes positivos para leitura normal, zero para EOF e menos um para erro.”

Sobre BUFFER_SIZE

“O valor de BUFFER_SIZE não muda a lógica do algoritmo. Ele só altera quantos bytes são lidos por chamada.”
